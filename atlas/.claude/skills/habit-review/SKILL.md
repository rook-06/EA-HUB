# Skill: Habit Review

Audit Damien's active habits — what's working, what's slipping, what to redesign.

## When to use

When Damien wants to take stock of his habits, when something isn't sticking, or on a regular cadence (monthly works well for most people).

## How to run

### Step 1 — Load context

Read: `context/growth.md` for the current habit list and notes.

### Step 2 — Get current state

Ask Damien to rate each active habit quickly: still doing it / inconsistent / dropped it.
Don't make this a long discussion — the rating is just data.

### Step 3 — Diagnose what's slipping

For any habit marked inconsistent or dropped: ask one question — what's getting in the way?
Listen for the real answer (schedule? motivation? wrong cue? wrong reward?). Don't assume.

### Step 4 — Redesign or drop

For each slipping habit, one of three outcomes:
- **Fix the system** — identify the specific friction and remove it
- **Shrink it** — reduce it to a version he'll actually do
- **Drop it** — if it's not serving him anymore, let it go without guilt

### Step 5 — Update the record

Update `context/growth.md` with any changes to the habit list.
Log any significant decisions in `decisions/log.md`.

## Principles

- Systems beat willpower. If a habit isn't sticking, the design is probably wrong — not the person.
- Fewer habits done consistently beat a long list done poorly.
- Don't add new habits until existing ones are stable.
